# Архитектура MassTracker

| Каталог                  | Ответственность                                                                   |
| ------------------------ | --------------------------------------------------------------------------------- |
| `app/`                   | Корневой маршрут, обработка ошибок и маршруты пяти вкладок.                       |
| `src/features/startup/`  | Порядок инициализации, срок ожидания, состояния загрузки и повторная попытка.     |
| `src/features/settings/` | Настройки приложения, профиль и чтение и запись выбранной темы через репозиторий. |
| `src/features/calendar/` | Календарные даты и дата, общая для экранов «Сегодня» и «Питание».                 |
| `src/features/demo/`     | Демонстрационные данные и экраны «Сегодня», «Питание», «Тренировки», «Прогресс».  |
| `src/components/`        | Общая компоновка, кнопки, карточки, календарь, индикаторы, график и диалоги.      |
| `src/database/`          | Общий контракт настроек, IndexedDB и SQLite, миграции и репозитории.              |
| `src/features/pwa/`      | Состояние сети, установка, тема документа и применение веб-обновлений.            |
| `public/`, `scripts/`    | HTML-шаблон, manifest, иконки, заголовки Pages и сборка Service Worker.           |
| `src/theme/`             | Цвета, типографика, размеры, отступы, выбор темы и её применение к навигации.     |
| `tests/`                 | Сценарии запуска, миграции, репозиторий и интерактивность вкладок.                |

Маршруты подключают экраны из `src`. Функциональные модули обращаются к данным через репозитории. Все SQL-операции остаются в слое базы. База данных независима от React и навигации. Псевдоним `@/` указывает на `src/` в TypeScript, Metro и Jest.

Все интерфейсные иконки проходят через `src/components/app-icon.tsx`. Тип `AppIconName` ограничивает доступный набор Lucide, цвета берутся из общей темы. Прямые импорты отдельных иконок по публичным subpath библиотеки исключают включение полного каталога Lucide в Metro bundle. На вебе используется inline SVG, на iOS — тот же `react-native-svg`, включённый в Expo Go SDK 58.

## Запуск и настройки

1. Корневой маршрут монтирует навигационный контейнер. Для экрана загрузки используется системная тема.
2. Компонент запуска ожидает открытие локального хранилища и применение миграций. Metro разрешает `settings-storage.web.ts` для браузера и `settings-storage.ts` для нативной платформы.
3. Загрузчик читает настройки. Вкладки монтируются с сохранённой темой и локалью. При отсутствии корректного значения темы используется системный режим.
4. При ошибке запуска или истечении времени ожидания веб-версия открывает вкладки с настройками по умолчанию. В профиле доступна повторная попытка. Нативная версия показывает существующий экран повторного запуска. Корневая граница Expo Router обрабатывает ошибки рендера маршрутов.
5. При смене темы профиль ожидает подтверждения записи. Контекст публикует новое значение после фиксации операции. При сбое сохраняется текущий режим и появляется сообщение с возможностью повторить попытку.

## Календарь и демонстрационные данные

Выбранная дата живёт в общем провайдере вкладок. По умолчанию он следует за датой устройства, в том числе при смене дня. Примеры дневного питания и воды отображаются на сегодняшней дате. Источник примеров — `demo-data.ts`. Они хранятся только в памяти приложения.

## Offline-first

Для веба используется SPA Expo Router. `npm run build:web` выполняет экспорт Expo, затем `scripts/pwa-export.cjs` сканирует окончательный `dist` и формирует `sw.js` и диагностический `precache-manifest.json`. В список входят HTML по URL `/`, все ленивые JS-модули, CSS, локальные шрифты, SVG, изображения и manifest. Служебные файлы хостинга, sourcemaps и сам SW исключены. Генератор проверяет локальные ссылки оболочки, CSS url() и иконок manifest; внешние критические ссылки отклоняются. Версия кеша зависит от содержимого файлов и шаблона SW; для каждого ресурса, включая итоговый HTML, записан SHA-256.

SW загружает ресурсы пакетами до шести одновременно с проверкой integrity, запретом redirect и сроком ожидания 15 секунд на ресурс. Установка завершается только после записи всего набора; неудачный кандидат удаляет только собственный неполный кеш и не активируется. Ответ HTML вместо JS/PNG тоже отклоняется по integrity. Существующая версия остаётся рабочей при сбое обновления.

`src/features/pwa/offline-support.ts` управляет повторной регистрацией, наблюдением установки и проверкой готовности через MessageChannel. Наличие контроллера само по себе не считается готовностью. Активный SW подтверждает наличие всех ресурсов в своём кеше; недостающие ресурсы восстанавливаются онлайн. Проверки выполняются при запуске, возврате видимости, смене сети, смене контроллера и по кнопке. Регистрация и проверка обновлений не блокируют чтение IndexedDB и показ вкладок. Время ожидания сообщений и подготовки ограничено; ошибки видны в профиле.

Плагин `scripts/web-asset-paths.cjs` меняет сегменты `/node_modules/` на `/vendor/` только в путях с маркером production-экспорта `?export_path=`. Он выполняется до генерации JavaScript-ссылок, хешированных имён и файлов ресурсов: пути JS, экспорта и precache совпадают. Cloudflare Pages не отбрасывает эти файлы. Нативные и dev-пути сохраняются. SVG-иконки входят в JS и не требуют отдельного шрифта.

Активная версия обслуживает навигацию по пяти маршрутам из кешированной оболочки и отдаёт только ресурсы из списка сборки. Если оболочка недоступна, используется сеть с ограниченным ожиданием или русскоязычная страница повторной загрузки. Пользовательские данные хранятся в IndexedDB и не входят в список Cache Storage. Версия схемы независима от хеша сборки.

Новая версия ждёт активации, пока используется предыдущая. Кнопка обновления приостанавливает приём новых записей настроек, ждёт фиксации или отката текущих операций и запрашивает активацию. Service Worker откладывает ручную активацию при других открытых окнах. После смены контроллера текущая страница перезагружается один раз. При активации удаляются только старые кеши точного формата `masstracker-app-<20 hex>`. Чужие кеши и IndexedDB не затрагиваются. При закрытии всех окон браузер может активировать подготовленную версию сам.

Хранилище и навигация не требуют backend. Обычный веб-запуск Metro не регистрирует Service Worker. Для Expo Go Metro обслуживает код при разработке.

## Расширение

Следующие функциональные модули размещаются в `src/features/` на своём этапе. Слои используют типизированные контракты и зависят от нижележащих слоёв. Изменения схемы добавляются новой миграцией. Зависимости вне Expo Go потребуют согласованного перехода к отдельной нативной сборке.
