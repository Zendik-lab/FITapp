# Архитектура MassTracker

| Каталог                   | Ответственность                                                                   |
| ------------------------- | --------------------------------------------------------------------------------- |
| `app/`                    | Корневой маршрут, обработка ошибок и маршруты пяти вкладок.                       |
| `src/features/startup/`   | Порядок инициализации, срок ожидания, состояния загрузки и повторная попытка.     |
| `src/features/settings/`  | Настройки приложения, профиль и чтение и запись выбранной темы через репозиторий. |
| `src/features/profile/`   | Модели, валидация, provider профиля, анкета, редактор разделов и сводка.          |
| `src/features/nutrition/` | Чистый движок BMR/TDEE/БЖУ, рекомендации, общий контекст целей и калькулятор.     |
| `src/features/calendar/`  | Календарные даты и дата, общая для экранов «Сегодня» и «Питание».                 |
| `src/features/demo/`      | Демонстрационные данные и экраны «Сегодня», «Питание», «Тренировки», «Прогресс».  |
| `src/components/`         | Общая компоновка, кнопки, карточки, календарь, индикаторы, график и диалоги.      |
| `src/database/`           | Общий контракт настроек, IndexedDB и SQLite, миграции и репозитории.              |
| `src/features/pwa/`       | Состояние сети, установка, тема документа и применение веб-обновлений.            |
| `public/`, `scripts/`     | HTML-шаблон, manifest, иконки, заголовки Pages и сборка Service Worker.           |
| `src/theme/`              | Цвета, типографика, размеры, отступы, выбор темы и её применение к навигации.     |
| `tests/`                  | Сценарии запуска, миграции, репозиторий и интерактивность вкладок.                |

Маршруты подключают экраны из `src`. Функциональные модули обращаются к данным через репозитории. Все SQL-операции остаются в слое базы. База данных независима от React и навигации. Псевдоним `@/` указывает на `src/` в TypeScript, Metro и Jest.

`ScreenSafeArea` и `AppTabBar` разделены на web/native адаптеры. Expo Router 58 возвращает нулевые Safe Area контексты на web; CSS `env(safe-area-inset-*)` является источником веб-геометрии. Верхний/боковые края принадлежат экрану, нижний — панели вкладок. Полноэкранная форма/состояние запуска учитывает также нижний край. Редактор внутри вкладки передаёт `withinTabs`, исключая повторный inset. Нативная версия использует прежние `SafeAreaView` и штатный `BottomTabBar`. Это адаптация представления, без изменения маршрутизации или слоя данных. [Аудит и проверки](UI-UX-AUDIT.md).

Все интерфейсные иконки проходят через `src/components/app-icon.tsx`. Тип `AppIconName` ограничивает доступный набор Lucide, цвета берутся из общей темы. Прямые импорты отдельных иконок по публичным subpath библиотеки исключают включение полного каталога Lucide в Metro bundle. На вебе используется inline SVG, на iOS — тот же `react-native-svg`, включённый в Expo Go SDK 58.

## Запуск и настройки

1. Корневой маршрут монтирует навигационный контейнер. Для экрана загрузки используется системная тема.
2. Компонент запуска ожидает открытие локального хранилища и применение миграций. Metro разрешает `settings-storage.web.ts` для браузера и `settings-storage.ts` для нативной платформы.
3. Загрузчик читает настройки. Вкладки монтируются с сохранённой темой и локалью. При отсутствии корректного значения темы используется системный режим.
4. При ошибке запуска или истечении времени ожидания веб-версия открывает вкладки с настройками по умолчанию. В профиле доступна повторная попытка. Нативная версия показывает существующий экран повторного запуска. Корневая граница Expo Router обрабатывает ошибки рендера маршрутов.
5. При смене темы профиль ожидает подтверждения записи. Контекст публикует новое значение после фиксации операции. При сбое сохраняется текущий режим и появляется сообщение с возможностью повторить попытку.

## Календарь и демонстрационные данные

Выбранная дата живёт в общем провайдере вкладок. По умолчанию он следует за датой устройства, в том числе при смене дня. Примеры дневного питания и воды отображаются на сегодняшней дате. Источник примеров — `demo-data.ts`. Они хранятся только в памяти приложения.

## Offline-first

Для веба используется SPA Expo Router. `npm run build:web` выполняет экспорт Expo, затем `scripts/pwa-export.cjs` сканирует окончательный `dist` и формирует `sw.js`, `version.json` и диагностический `precache-manifest.json`. В список кеширования входят HTML по URL `/`, все ленивые JS-модули, CSS, локальные шрифты, SVG, изображения и manifest. Служебные файлы хостинга, sourcemaps, JSON проверки версии и сам SW исключены. Генератор проверяет локальные ссылки оболочки, CSS url() и иконок manifest; внешние критические ссылки отклоняются. Каждый production-запуск получает новый случайный ID, согласованный с HTML и worker. Для каждого ресурса, включая итоговый HTML с метаданными, записан SHA-256. Стабильные URL ресурсов HTML помечаются `app-build`, чтобы выбирать кеш своего документа.

SW загружает ресурсы пакетами до шести одновременно с проверкой integrity, запретом redirect и сроком ожидания 15 секунд на ресурс. Установка завершается только после записи всего набора; неудачный кандидат удаляет только собственный неполный кеш и не активируется. Ответ HTML вместо JS/PNG тоже отклоняется по integrity. Существующая версия остаётся рабочей при сбое обновления.

`src/features/pwa/offline-support.ts` управляет повторной регистрацией, наблюдением установки и проверкой готовности через MessageChannel. Наличие контроллера само по себе не считается готовностью. Активный SW подтверждает наличие всех ресурсов в своём кеше; недостающие ресурсы восстанавливаются онлайн. Проверки выполняются при запуске, возврате видимости, смене сети, смене контроллера и по кнопке. Регистрация и проверка обновлений не блокируют чтение IndexedDB и показ вкладок. Время ожидания сообщений и подготовки ограничено; ошибки видны в профиле.

Плагин `scripts/web-asset-paths.cjs` меняет сегменты `/node_modules/` на `/vendor/` только в путях с маркером production-экспорта `?export_path=`. Он выполняется до генерации JavaScript-ссылок, хешированных имён и файлов ресурсов: пути JS, экспорта и precache совпадают. Cloudflare Pages не отбрасывает эти файлы. Нативные и dev-пути сохраняются. SVG-иконки входят в JS и не требуют отдельного шрифта.

HTML использует Network First с четырёхсекундным тайм-аутом, no-store и integrity текущего документа. Новый HTML не смешивается со старым worker: до согласованного применения обновления используется кеш текущей сборки. При сетевом сбое и отсутствии оболочки возвращается русскоязычная страница повторной загрузки. Ресурсы выбираются из кеша своего документа; потерянные ресурсы восстанавливаются с integrity. Хешированные ресурсы предшественников доступны оставшимся старым окнам. Пользовательские данные хранятся в IndexedDB вне Cache Storage. Версия схемы независима от ID сборки.

Новая версия ждёт активации, пока используется предыдущая. Проверки worker и `version.json` выполняются при запуске, возобновлении, восстановлении сети и вручную. «Позже» откладывает уведомление. Применение блокируется общей защитой открытых форм/диалогов, приостанавливает новые записи и ждёт commit всех принятых операций. При ошибке сохранения обновление отменяется. После проверки полного кеша worker проверяет другие окна перед skipWaiting. Один явный reload после смены контроллера защищён sessionStorage по целевому ID; произвольный controllerchange не вызывает reload. Кеши предшественников точного формата `masstracker-app-<20 hex>` фиксируются до начала установки, чтобы не удалить устанавливаемого преемника, и удаляются после подтверждения новой сборки при единственном окне приложения. Чужие кеши и IndexedDB не затрагиваются. При закрытии всех окон браузер может активировать подготовленную версию сам. [Подробности этапа 02.1](STAGE-02.1.md).

Хранилище и навигация не требуют backend. Обычный веб-запуск Metro не регистрирует Service Worker. Для Expo Go Metro обслуживает код при разработке.

## Расширение

Этап 03 добавляет `src/features/nutrition/`: чистый движок, разрешение рекомендаций/ручных целей, общий `NutritionProvider`, калькулятор и сводку. Provider внутри `ProfileProvider`/`OnboardingGate` читает `nutrition_state` перед записью. Все экраны получают цели из одного контекста; автоматические снимки пересчитываются по профилю и возрасту, ручные значения сохраняются. `getDailyNutrition` принимает реальные дневные итоги; до этапа 04 используется ноль. Экран повторяет паттерн редактора внутри вкладки. [Подробности](STAGE-03.md).

Этап 02 добавляет `ProfileProvider` внутри существующих `StartupGate`, темы и `PwaProvider`. До чтения профиля показывается состояние загрузки с ограничением 10 секунд и повторной попыткой при сбое. `OnboardingGate` монтирует анкету вместо вкладок, пока `completed=false`; текущий URL не меняется. Поэтому прямой `/nutrition` также проходит gate. После подтверждения выполняется `router.replace('/')`. Завершённый пользователь сразу получает прежние пять вкладок.

`profile-context.ts` отделяет потребление данных от загрузки и хранения. Поля `profile-fields.tsx` и бизнес-валидация общие для анкеты и редактора; `form-controls.tsx` и `form-screen.tsx` владеют вводом, блокировкой, клавиатурой, безопасными областями и коротким переходом с учётом reduced motion. Редактор открывается внутри вкладки профиля, не создавая новую схему навигации. Пользователь видит успешное сохранение только после commit. «Сегодня» берёт имя и вес из контекста проверенного локального профиля, не из демоданных.

Репозиторий профиля зависит от контракта `SettingsStorage`, моделей и чистой валидации; React, роутер и платформенные SQL/IndexedDB API ему не нужны. Очередь всех записей находится в общем `settings-writes.ts`, чтобы процедура обновления PWA видела и ожидала каждую принятую операцию. При ошибке ожидания обновление отменяется, при незаписанном редакторе его кнопка заблокирована.

Следующие функциональные модули размещаются в `src/features/` на своём этапе. Слои используют типизированные контракты и зависят от нижележащих слоёв. Изменения схемы добавляются новой миграцией. Зависимости вне Expo Go потребуют согласованного перехода к отдельной нативной сборке.
