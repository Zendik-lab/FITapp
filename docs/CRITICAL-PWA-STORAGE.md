## Хранение и границы диагноза

Web/PWA использует IndexedDB `masstracker` v2, store `app_settings`. Native использует SQLite `masstracker.db` и миграции 1–2. Схема не менялась. `user_state` хранит черновик/шаг анкеты, профиль, цели, параметры тела, активности, тренировок и питания. Тема хранится отдельно. Демонстрации остаются в памяти.

Чтение и валидация завершаются до отображения личного профиля. Defaults не записываются поверх сохранённых данных при запуске. Записи сериализованы и подтверждаются завершением транзакции. Ошибки не очищают базу. SQL остаётся параметризованным в слое данных.

В настоящем production Chromium введён черновик, браузер полностью закрыт и запущен с тем же каталогом профиля. Черновик восстановился из IndexedDB. Локальные проверки проходят настоящее анкетирование, цели, тему, офлайн-изменения и полные перезапуски браузера.

Найдена воспроизводимая причина частичной потери ответов: `ProfileFields` формировал весь черновик из значения предыдущего render. Два быстрых callback разных полей до нового render приводили к записи второго снимка с пустым первым полем. В финальном WebKit-прогоне исчезла дата рождения при сохранённых имени/весе; отдельный детерминированный Jest-тест воспроизвёл пустую дату после изменения роста без браузерных таймингов. Исправление: функциональные обновления полей применяются к последнему черновику, включая вычисление связанного целевого веса. Регрессионный тест прошёл после изменения.

Эта воспроизведённая гонка не объявляется объяснением всех WebKit-отказов. После её исправления в одном общем прогоне вновь не восстановилась дата; отдельный цикл 12 вводов/reload с журналом DOM-событий и снимков `user_state` прошёл 12/12. Браузерный сценарий дополнен ожиданием признака принятия события моделью (рассчитанный возраст), а не только DOM-значения, установленного автоматизацией.

**Связь с исчезновением всего профиля на конкретном iPhone не установлена.** Доступа к его базе и установленной оболочке нет. Изоляция origin/режимов, ограничения браузера и очистка iOS не объявляются доказанной причиной.

Добавлен запрос `durability: strict` для readwrite IndexedDB; старый WebKit без третьего аргумента использует совместимый вызов. Это усиление фиксации записи, а не доказательство устранения неизвестной ошибки устройства. Сохранён запрос `navigator.storage.persist()` в установленной PWA; он не гарантирует защиту от системной очистки.

## Исправления

- `build:web` заранее создаёт уникальный ID, передаёт `NODE_ENV=production` и `EXPO_PUBLIC_BUILD_ID` Expo, затем записывает тот же ID в HTML/worker/JSON. Клиент умеет получить ID из самого JS при отсутствии HTML-метаданных. Production без ID обозначается неполной публикацией.
- Экспорт идёт в новый `.expo/web-build-<id>`. Метаданные генерируются по окончательным файлам. После проверки набор копируется в `dist`, который проверяется повторно. Копирование совместимо с работающим Metro на Windows: переименование занятого `dist` возвращало EPERM. Старые неизменяемые JS с хешами могут оставаться для старых окон, но не входят в новый precache. Ошибка сборки/проверки возвращает ненулевой код; такой артефакт публиковать нельзя.
- Добавлены `.node-version` и `wrangler.jsonc` с output `dist`. Имя `fitapp` взято из существующей документации; его нужно сверить перед deployment. Wrangler не устанавливает Build command панели: там требуется **`npm run build:web`**, root репозитория, output **`dist`**. Отдельного `expo export` или загрузки `public` недостаточно.
- Сохранена автоматическая подготовка после первого успешного production-запуска, при возврате и восстановлении сети. Worker `/sw.js`, scope `/`, `updateViaCache: none`. Кеш содержит shell, все ленивые JS-вкладки, CSS, изображения/иконки и любые экспортированные локальные шрифты. Текущий UI использует системный шрифт и встроенные SVG без CDN.
- «Подготовить офлайн-режим» ремонтирует активный кеш независимо от `/version.json`; при отсутствии worker повторяет регистрацию. «Проверить обновления» отдельно проверяет worker и JSON без HTTP-кеша. Готовность требует полного кеша согласованной сборки. Проверяются SRI и MIME; ошибки содержат ресурс и исходную причину.
- Redundant worker не может ответить клиенту, поэтому ошибка установки сохраняется в отдельном `masstracker-diagnostics`. Успешный повтор снимает ошибку этой же сборки; старые попытки не выдаются за новые. Там же сохраняется время последней проверки для офлайн-перезапуска. Профиль туда не записывается.
- Недоступный `sessionStorage` больше не блокирует явное обновление. Если он доступен, сохранены отметка reload и подтверждение установленной версии. Формы, второе окно и незавершённые записи продолжают защищать активацию. Native показывает собственные сведения о версии; Web Service Worker к native не применяется, Expo OTA не настроен и не имитируется.
- Кандидат полностью скачивается до применения. Ошибка установки удаляет только незавершённый кеш кандидата. Чтение готовности и ремонт не удаляют предшественника. Очистку разрешает отдельное `CONFIRM_APP_READY` после успешного восстановления профиля; проверяются ID, кеш и другие окна. IndexedDB, SQLite, localStorage и чужие кеши не очищаются.
- Закрытая по умолчанию диагностика профиля использует прежние `Card`, `AppText`, `PrimaryButton`, темы и токены. Есть клавиатурное управление и `aria-expanded`. Показываются версия/ID, окружение, режим запуска/origin, worker/scope/контроль/версия, кеш/число ресурсов, backend хранения, последняя подтверждённая запись, последняя проверка обновлений и конкретная ошибка. Время записи восстанавливается из существующих `updatedAt` профиля/темы. Просмотр не пишет пользовательские данные. Ремонт кеша не снимает ошибку последней проверки версии: он не подтверждает доступность `/version.json`.

```powershell
npm.cmd run typecheck
```

Нужны авторизация Cloudflare и правильное имя существующего проекта. Не заменяйте текущий origin новым: данные привязаны к origin. Для Git integration задайте Build command `npm run build:web`, output `dist`, root репозитория; push этим заданием не разрешён. Не удаляйте установленную PWA и не очищайте IndexedDB/данные Safari для исправления обновления.

При ручном выполнении каждой предыдущей команды требуется exit code 0. При любой ошибке остановиться до deployment; приведённая проверка после Playwright не заменяет проверку типов, lint, Jest и артефакта.

## Приёмка iPhone после публикации

1. Открыть существующую установленную PWA онлайн. Проверить Production, новый ID, worker activated, scope текущего origin `/`, контроль «да» и полный кеш. Новую установку добавить через Safari на экран «Домой», затем дождаться готовности внутри установленной PWA.
2. Изменить имя, цель и тему, сохранить и проверить время записи. Выгрузить приложение свайпом, открыть снова и проверить значения.
3. Выгрузить приложение, включить авиарежим, запустить с экрана «Домой». Проверить пять вкладок и данные, внести офлайн-изменения, сохранить, закрыть и снова открыть в авиарежиме.
4. Вернуть сеть. После отдельной разрешённой публикации следующего ID проверить «Позже», затем «Обновить», сохранение данных и ещё один холодный офлайн-запуск.
5. При ошибке записать ID, origin, scope, кеш, время записи и полный текст причины из диагностики именно установленной PWA. Сохранить приложение и базу для исследования.
