# Этап 05.2 — интерфейс и умные функции FITapp

## Аудит и изменения

- «Сегодня» сохраняет кольцо КБЖУ, добавляет быстрый вход в дневник, подбор блюд и контекстную подсказку. Настройки управляют приветствием и порядком необязательных карточек.
- «Питание» использует существующие формы дневника и рецептов. Добавлены перенос дня, повторяемое без дубликатов копирование приёмов, Undo, поиск с задержкой обработки запроса, история, частые продукты и сортировка. Свайп вправо открывает запись, влево удаляет с возможностью отмены. Рядом доступны обычные кнопки.
- «Инструменты питания» открывают холодильник, сравнение, покупки и бюджет. Запасы приводятся к граммам через коэффициенты каталога. Холодильник показывает остаток по каждому недостающему ингредиенту. Список покупок объединяет незакрытые позиции с одинаковыми идентификаторами. Цены упаковок и лимиты задаёт пользователь в тенге.
- «Прогресс» показывает Mass Coach, текущую и максимальную серии, календарь, достижения, недельный отчёт и FIT Wrapped. В отчётах учитываются записи пользователя. Средние считаются по дням с записями. Для проверки выполнения используется диапазон ±10% текущих целей. FIT Wrapped предлагает поделиться PNG или текстовым итогом по подтверждению, если платформа поддерживает системную отправку.
- «Профиль» сохраняет выбор акцента, интенсивность движения, тактильную отдачу, мотивационные сообщения и порядок карточек. Порядок меняется перетаскиванием за ручку или кнопками. Выбор светлой, тёмной и системной темы доступен в «Оформлении».
- При запуске знак бренда анимируется параллельно открытию хранилища. После готовности интерфейс становится интерактивным сразу. Общие формы, диалоги, Safe Area и актуальные статусы PWA переиспользуются.

## Архитектура и данные

Бизнес-логика находится в `src/features/smart` и использует существующие модели продуктов, рецептов и целей. Рекомендации рассчитываются локально по КБЖУ, размеру порции, цели, истории, избранному и доступным сведениям о рецепте. При указанных аллергиях или ограничениях автоматический подбор приостановлен, поскольку каталог не содержит надёжной классификации аллергенов. Пользовательские цены применяются к порциям, ингредиентам и дневнику. Для рецептов с полными ценами доступна сортировка по стоимости с учётом лимитов.

В документе `food_diary_state` добавлены необязательные компоненты запасов, покупок, цен, истории, достижений, происхождения копий и снимка количества ингредиентов. Репозиторий проверяет их при чтении и записи. Существующая атомарная операция сравнивает сохранённую версию перед записью. Настройки представления хранятся в отдельном ключе `personalization.v1`. Структуры SQLite и IndexedDB остаются совместимы с миграциями 1–5. Чтение прежнего документа применяет пустые состояния без перезаписи пользовательских данных. Зависимости остаются прежними.

## Исправления по результатам проверок

- После сохранения персонализации форма сравнивала одинаковые данные с разным порядком ключей. Представление теперь нормализуется в одном порядке. Браузерный сценарий проверяет сохранение и открытие приложения без сети.
- Smart Meal ошибочно пропускал импортированные справочные продукты с заполненными КБЖУ. Алгоритм теперь использует эти данные с пометкой об источнике. Тест проверяет, что в каталоге находится вариант из двух продуктов.
- Фирменный стартовый экран унаследовал Safe Area и прокрутку общего экрана состояния. Статус загрузки остаётся заголовком для средств доступности.
- Порция после редактирования открывает дату, указанную при сохранении. Удаление сверяет актуальный снимок перед записью, а Undo возвращает сохранённую порцию с прежним идентификатором.

## Ограничения

- Полноценная динамика веса требует журнала измерений этапа 07. Отчёты используют доступные записи питания, а текущий вес берут из профиля.
- Стоимость старых записей блюд без снимка ингредиентов остаётся неизвестной. Исторические суммы пересчитываются по текущим пользовательским ценам.
- Текстовые диеты с произвольными условиями требуют структурированных свойств каталога. Разметка аллергенов отсутствует. У полноты каталога сохраняются критерии этапа 05.1.
- Доступность экспорта FIT Wrapped зависит от системной отправки. Браузер передаёт PNG при поддержке обмена файлами, остальные поддерживаемые режимы передают текст. Интеграция с планировщиком, Apple Health и прочими будущими этапами следует основной дорожной карте.

## Запуск и приёмка на iPhone

Для локальной PWA выполните `npm run build:web`, затем `npm run serve:web`. Для нативного режима разработки используйте `npm start`.

1. Откройте сборку в Safari по разрешённому HTTPS-адресу. Проверьте первый запуск, переход к анкете, отсутствие вспышек и появление главной вкладки.
2. Установите PWA на экран «Домой». Дождитесь «Доступно без интернета», закройте приложение, включите авиарежим и откройте PWA повторно.
3. Введите дробную порцию, пролистайте календарь, повторите перенос одного дня. Проверьте свайпы, обычные кнопки, Undo, фокус клавиатуры и сохранение после перезапуска.
4. Добавьте запас, отправьте недостающие ингредиенты в покупки, задайте цены и проверьте суммы. Добавьте вариант из подбора блюд и откройте отчёты.
5. Проверьте светлую и тёмную темы, четыре акцента, крупный текст, VoiceOver, Reduce Motion, перетаскивание карточек, тактильную отдачу в Expo Go и появление достижения только при событии. Проверьте системное меню отправки итоговой карточки.
6. Проверьте портретную ориентацию, узкий экран, клавиатуру и системные области. Отдельно проверьте обновление ранее установленной PWA через штатную карточку.
