# MassTracker — глобальный аудит UI/UX, 26.11.2026

Проверены существующие интерфейсы этапов 01.1, 02 и 02.1. Исправления внесены в исходный код. Apple Minimal, пять вкладок, демонстрации предыдущих этапов, профиль, цели, IndexedDB/SQLite и Service Worker сохранены. Этап 03 не начат; публикация и push не выполнялись.

**Итог:** все семь запрошенных команд прошли под Node.js 22.16.0: 88 модульных тестов и 101 браузерный сценарий, без ошибок. Один сценарий ненулевых CSS inset намеренно выполняется только в Chromium через CDP. Физическая приёмка iPhone / Expo Go остаётся отдельным обязательным шагом.

## Причины и исправления

### Safe Area и системная строка

Установленный Expo Router 58 в `build/SafeAreaProvider.js` использует на web `ZERO_INSETS` и `ZERO_FRAME`. Поэтому прежние `SafeAreaView` и `useSafeAreaInsets().bottom` возвращали нулевые отступы. `viewport-fit=cover` уже присутствовал и сам по себе проблему не решал. Заголовок и верхняя граница прокрутки оставались в системной области, а нижняя панель не резервировала Home Indicator.

Введены платформенные адаптеры `ScreenSafeArea` и `AppTabBar`. На web CSS `env(safe-area-inset-*)` применяется непосредственно браузером, включая поворот экрана. Верхняя и боковые области принадлежат экрану, нижняя — панели навигации. Полноэкранная анкета и состояния запуска учитывают все края. Редактор внутри вкладки явно передаёт `withinTabs` и не добавляет нижний inset повторно. На native остаются `SafeAreaView` и штатный `BottomTabBar` Expo Router.

Убраны устаревший `apple-mobile-web-app-status-bar-style=black-translucent` и перекрывающий верхнюю область `body::before`. Цвет документа по-прежнему следует теме. Это следует актуальной рекомендации разработчика WebKit; фактические системные эффекты iOS 27 требуют проверки устройства. Размеры вроде 47/34 используются только как входные данные регрессионных тестов, в интерфейсе таких констант нет.

Источники: [Expo SDK 58: веб-контексты Safe Area](https://docs.expo.dev/versions/v58.0.0/sdk/safe-area-context/#context), [WebKit: CSS env и viewport-fit](https://webkit.org/blog/7929/designing-websites-for-iphone-x/), [WebKit: рекомендация убрать black-translucent](https://bugs.webkit.org/show_bug.cgi?id=317153#c2). Первая причина доказана исходным кодом зависимости и воспроизведена в браузере. Связь устаревшего meta-тега с конкретным размытием на пользовательском iPhone не проверена на устройстве.

### Адаптация и прокрутка

Проверены ширины 320, 375, 390, 393, 414, 430 и 1280 CSS px, а также альбомная геометрия 844×390 с боковыми inset. Для анкеты и шести редакторов все шесть телефонных ширин проверяются отдельно. На каждой вкладке измеряются горизонтальные границы, отсутствие прокрутки документа, достижение конца собственного ScrollView и положение его нижней границы относительно навигации. Горизонтальная прокрутка недели календаря является намеренной и проверяется отдельно от переполнения страницы.

Панель получает фон до нижнего края и остаётся в потоке компоновки. Внешняя область навигации полная по ширине; сами пять вкладок центрированы и ограничены 640 px. Найденное при ревью смещение панели на широком экране исправлено `display:flex` у её веб-обёртки и проверено измерением координат.

`StatusScreen` теперь прокручивается: длинная ошибка и повторная попытка доступны даже при высоте 240 px. Сохранены динамическая высота `100dvh`, существующая обработка VisualViewport при вводе и единственный основной ScrollView каждого экрана. Нет новых фиксированных панелей поверх контента. Добавлен общий baseline полос прокрутки с цветом общей темы и режимом forced colors.

### Клавиатура и поля

Все TextInput находятся в `FormField` / `ProfileFields`; их ключи привязаны к именам полей, ref регистрируется стабильным callback. Компоненты не объявляются внутри render как новые типы. Существующий фикс `keyboardDismissMode="none"` для web сохранён.

Проверяются посимвольный текстовый, целочисленный и дробный ввод, точка/запятая, замена выделения, курсор, автосохранение, ошибка записи, прокрутка и изменение viewport. Проверен фокус ошибочного поля редактора. В iOS-форме `KeyboardAvoidingView` остаётся единственным механизмом компенсации клавиатуры: одновременный `automaticallyAdjustKeyboardInsets` удалён. CSS сохраняет размер полей не менее 16 px и не запрещает пользовательский zoom. Реальная клавиатура Safari не эмулируется изменением viewport.

### Единообразие и доступные состояния

Палитра, системный шрифт, карточки, кнопки, иконки и скругления сохранены. В «Прогрессе» выбранный период получил явный `aria-selected`; в настройках темы используется общий `RadioGroup` со стрелками, пробелом, `aria-checked` и одним пунктом в Tab-порядке. Ранее состояние темы и периода визуально отображалось, но не передавалось в веб-разметку через один только `accessibilityState`.

Диалоги сохраняют `showModal()`, блокировку фона, Escape и возврат фокуса. Проверены сохранение/отмена изменений, подтверждение повторного анкетирования, будущие действия и тема. Длинные имя и пищевой режим, светлая/тёмная тема и низкий viewport проверяются браузерными сценариями. Снимки форм делаются после завершения существующего fade; анимация не принимается за пустой экран.

## Среда проверок: Node.js и WebKit в Windows

В системной среде Node.js 26.13.1 / Playwright 1.65.1 / WebKit 27.2 v2388 нестабильно создавалась сама страница: `browserContext.newPage: Target page, context or browser has been closed`, в протоколе есть `Target.targetDestroyed` с `crashed:true` до навигации. Это повторилось в отдельном минимальном тесте пустой страницы без импорта MassTracker, сервера приложения, CSS или IndexedDB. Повторная установка WebKit не устранила сбой. Дополнительная проба получила `worker process exited unexpectedly (code=3221226505)`.

Один прогон также зарегистрировал вставку продолжения числа в начало (`80,51` вместо `180,5`) при сохранённом фокусе. В отдельных диагностических сериях вне worker runner — 20 и 40 повторений — расхождение не повторилось. Оно не замаскировано принудительным переносом каретки или ослаблением проверки. Синхронное управление selection в код приложения не добавлялось без установленной причины.

Изолированно скачан официальный Node.js 22.16.0, соответствующий `.node-version`; SHA-256 архива сверен с официальным SHASUMS256. Системная установка не менялась. Под этой версией прошли три пробы пустой страницы, все четыре ранее упавших теста и окончательный полный набор из 101 браузерного сценария. ## Ручная приёмка

### Safari на iPhone

- [ ] Открыть каждую вкладку и прокрутить до конца в обеих темах, портретной и альбомной ориентации. Заголовок не пересекает системную строку; последняя карточка доступна; второй прокрутки документа и горизонтального сдвига нет.
- [ ] Проверить изменение высоты браузерных панелей при прокрутке, увеличение текста и pinch zoom. Шрифты полей не вызывают самопроизвольный zoom.
- [ ] Последовательно вводить имя, дату, целые и дробные значения, в том числе запятую и замену цифры в середине. Прокрутить форму при открытой клавиатуре, открыть/закрыть клавиатуру, сохранить/отменить изменения.

### Установленная iOS PWA

- [ ] После разрешённой публикации обновить существующую установленную PWA через штатное предложение. Не очищать данные сайта и не переустанавливать приложение для обхода кеша.
- [ ] В светлой и тёмной теме проверить цвет/контраст системной строки и отсутствие размытия именно заголовка. Проверить верх при первом запуске, возврате из фона и прокрутке.
- [ ] Проверить фон панели до самого нижнего края, Home Indicator и отсутствие двойного нижнего отступа в шести редакторах. Повторить после поворота.
- [ ] Проверить все восемь шагов анкеты на тестовом профиле; на существующем использовать подтверждённое повторное анкетирование без удаления хранилища.
- [ ] Включить авиарежим, закрыть и снова открыть PWA, пройти пять вкладок, изменить профиль, вернуть сеть и проверить сохранность. Проверить новую сборку/версию после обновления.
- [ ] Проверить диалоги, VoiceOver, фокус и действия при открытой клавиатуре. Системное оформление уже установленной PWA может отличаться от новой установки; записать фактическую версию iOS и результат, не приписывать эффект конкретному meta-тегу без проверки.

### Chrome на iOS

- [ ] Повторить навигацию, прокрутку, форму с клавиатурой и темы. Отдельно записать результат; он не следует из Chromium на компьютере.

### Expo Go

- [ ] Запустить на iPhone совместимый Expo Go SDK 58. Проверить SQLite, анкету, пять вкладок и шесть редакторов.
- [ ] Проверить Safe Area, Home Indicator, клавиатуру без двойной компенсации, скролл, диалоги, увеличенный системный текст и обе темы. После перезапуска профиль сохраняется.

## Команды запуска и последующей публикации

Для воспроизводимости используйте Node.js **22.16.0** из `.node-version`. В этой сессии проверенный официальный runtime дополнительно размещён в `.expo/node-runtime/node-v22.16.0-win-x64`; его можно подключить только к текущему PowerShell, не меняя системную установку. На другой машине установите указанную версию привычным менеджером версий.

Локальная production-проверка в текущем рабочем каталоге:

```powershell
Set-Location -LiteralPath 'D:\FitApp'
$env:Path = 'D:\FitApp\.expo\node-runtime\node-v22.16.0-win-x64;' + $env:Path
node --version # v22.16.0
npm.cmd run build:web
npm.cmd run verify:web
npm.cmd run serve:web
```

Открыть [локальную PWA](http://127.0.0.1:4174). На loopback доступен Service Worker. Для Expo Go: `npm.cmd run start -- --lan`. Для разработки web: `npm.cmd run start -- --web` (режим без production Service Worker).

Повтор браузерных проверок:

```powershell
npx.cmd playwright install chromium webkit
npm.cmd run test:offline
# Отдельный Chromium-прогон помогает отличить ошибки приложения от запуска WebKit:
npm.cmd run test:offline -- --project=chromium
```

После отдельного разрешения на публикацию, проверки имени существующего проекта Cloudflare и фактической production-ветки, команда из текущей инструкции проекта:

```powershell
npm.cmd run build:web
npm.cmd run verify:web
npx.cmd wrangler@latest pages deploy dist --project-name fitapp --branch main
```

Загружать весь `dist` одной согласованной публикацией. Для Git integration: Build command `npm run build:web`, output `dist`. После публикации сравнить HTML app-build, version.json и worker build ID, получить предложение обновления на прежнем origin и пройти ручную приёмку. Эти команды публикации в рамках аудита не выполнялись.
