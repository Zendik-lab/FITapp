# Stage 03 Nutrition Engine Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in the current branch, as explicitly requested. Track work with checkboxes.

**Goal:** Локальные индивидуальные калории и БЖУ без backend, с сохранением ручных целей.

**Architecture:** Чистый Nutrition Engine → модель рекомендаций и настроек → репозиторий SettingsStorage → общий NutritionProvider → существующие экраны и форма. Версионированный документ в app_settings не требует изменения схемы. Экран открывается внутри профиля/питания по существующему образцу ProfileEditor, пять вкладок сохраняются.

**Tech Stack:** Expo 58, React Native/Web, TypeScript strict, Jest, Playwright, IndexedDB/SQLite.

**Spec:** Приложенное пользователем полное задание «FITapp — Stage 03: Nutrition Calculation Engine»; итоговые решения и приёмка — docs/STAGE-03.md.

## Global Constraints

- Только этап 03; текущая ветка, без push и публикации.
- Формулы и коэффициенты точно из задания; взрослые 18–120 лет, без подстановки отсутствующего пола/даты/веса.
- Автоматические цели обновляются, ручные сохраняются; калории и БЖУ переключаются независимо.
- Для существующего поддержания поправка 0; для снижения выбран явный дефицит 350 ккал, без адаптации по весу.
- Калории округляются до целых перед расчётом БЖУ, граммы до десятых, допуск энергии БЖУ 2 ккал.
- Нет фиктивного потребления: пустой дневной итог равен нулю.
- Существующие FormScreen/FormField/ChoiceGroup, тема, Safe Area, очередь записей и Service Worker сохраняются.

## Review Focus

- Ошибка/повреждение хранилища не затирает документ начальными значениями.

- Ввод запятой и промежуточных строк не меняет курсор/идентичность TextInput.
- Недоступный расчёт (несовершеннолетний/неуказанный пол) предлагает исправить профиль.
- Полный production bundle, калькулятор и сохранение доступны при холодном офлайн-запуске.
