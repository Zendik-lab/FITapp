# Этап 02 — план реализации

**Цель:** реализовать пользовательское задание этапа 02 в существующем MassTracker.

**Архитектура:** типизированный агрегат профиля и черновика через существующий SettingsStorage; атомарная запись одного документа в SQLite / IndexedDB. Аддитивная миграция версии 2 сохраняет настройки. Общие поля и валидация используются анкетой и редактором разделов. Gate внутри существующего StartupGate скрывает вкладки до загрузки профиля и завершения анкеты, без новых URL.

**Стек:** текущий Expo / React Native / TypeScript / Expo Router, без новых зависимостей.

**Спецификация:** пользовательское задание «Этап 02 — Анкетирование пользователя и персональные цели»; AGENTS.md, ROADMAP.md, DESIGN.md.

## Ограничения

- Только этап 02; PWA основная, Expo Go дополнительная платформа.
- Сохранить пять вкладок, темы, PWA offline и демонстрации предыдущих этапов.
- На «Сегодня» реальные профиль и цель, отсутствие расчётов калорий и БЖУ.
- Без публикации и git push. Проверка на физическом iPhone требует ручной приёмки.

## Проверяемые риски

- Невозможная / будущая дата, день рождения и високосный год.
- Пустые, бесконечные, отрицательные числа, противоречие цели и веса.
- Перезапуск на незавершённом шаге и быстрые последовательные изменения.
- Ошибка записи: сохранить введённые значения и дать повторить; не подтверждать успех.
- Повторная анкета и редактирование не удаляют профиль и настройки.

## Решения

- Название продукта MassTracker сохраняется: FitApp — имя проекта в задании.
- Дата рождения вводится в формате ДД.ММ.ГГГГ, без новой нативной зависимости; ошибки возле полей.
- Рекомендованный ориентир темпа 0,25 кг/нед.; предупреждения не являются диагнозом и не обещают срок результата.
- Редактор разделов внутри вкладки профиля сохраняет существующую маршрутизацию; черновик анкеты пишется после каждого изменения без debounce.
- Этап 01.1 остаётся IN_PROGRESS; начало 02 явно разрешено заданием. Завершённость 02 отражается с учётом оставшейся физической приёмки.

## Ревью и уточнения

- Репозиторий использует единый атомарный документ поверх SettingsStorage; архитектура хранилища сохранена.
- Очередь перенесена в общий settings-writes: PWA-обновление должно видеть все принятые записи до их выполнения. Регрессионный тест сначала воспроизвёл потерю AB после A, затем прошёл после исправления.
- Поля формы заблокированы на время подтверждённого сохранения; тест сначала воспроизвёл доступность ввода во время commit, затем прошёл.
- Сбой принятой записи отменяет PWA-обновление, несохранённый редактор блокирует его кнопку.
- Финальный браузерный прогон: 22/22; Jest: 16 suites / 57 тестов. Подробности в docs/STAGE-02.md.
