Дата: 26.11.2026. Ветка: `main`, исходное рабочее дерево было чистым. Изменения выполнялись в существующем checkout. Этап **IN_PROGRESS** до приёмки физического iPhone, установленной PWA и Expo Go. Публикация, git push и переход к этапу 05 не выполнялись.

## Функциональность

В «Питании» работают четыре приёма: завтрак, обед, ужин, перекусы. Записи можно добавлять, редактировать, переносить в другой приём/дату, удалять и копировать. Приём целиком копируется на дату из общего календаря. Стрелки дневника переключают дни, заголовок даты открывает календарь месяца; есть возврат к сегодня. Предыдущий недельный вариант других экранов сохранён.

«Сегодня» и «Питание» получают реальные суммы из FoodProvider и цели из NutritionProvider этапа 03. Отображаются калории, БЖУ, процент, остаток либо спокойная формулировка превышения. На «Сегодня» добавлены последние три записи выбранного дня и рабочее быстрое добавление еды.

В bundle находятся **129** уникальных справочных продуктов из 15 категорий, включая сухие и готовые крупы/макароны. Все числа справочные, не гарантированные данные производителя. Общий ориентир состава — [USDA FoodData Central / SR Legacy](https://fdc.nal.usda.gov/); для местных молочных/готовых продуктов и порошков явно указаны приблизительные значения. Значения зависят от сорта, приготовления и бренда; приоритет у этикетки. Это база пищевых продуктов; рецептов и отдельного модуля спортивного питания нет.

Поиск не зависит от регистра, поддерживает части названия/бренда/штрихкода и пробелы, работает немедленно локально. Доступны разделы «Поиск», «Недавние», «Избранное», «Мои продукты». Недавние уникальны и упорядочены по последнему использованию. Свои продукты создаются, редактируются и удаляются. Название, категория, числа и штрихкод валидируются; необычная пищевая ценность сопровождается предупреждением. Дробные значения принимают запятую и точку, промежуточные расчёты не округляются.

Основная единица — граммы. Переводы доступны только с известным коэффициентом: вода — 1 г/мл; справочное варёное яйцо — 50 г съедобной части/штуку; пример протеина — 30 г/порцию. Коэффициенты видны при выборе единицы. Для остальных продуктов неизвестные единицы не предлагаются.

## Open Food Facts и камера

OFF — дополнительный запрос к публичному API без backend/ключа. Кнопка онлайн-поиска запускает задержку 500 мс; интервал между поисками не менее 6,5 с, таймаут 10 с. Изменение/очистка запроса и закрытие экрана отменяют запрос/устаревший результат. Такая реализация учитывает [ограничения OFF](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/), где не рекомендуется поиск при каждом введённом символе. Атрибуция и ссылка на [ODbL/условия](https://world.openfoodfacts.org/terms-of-use) доступны в поиске и карточках. Web передаёт `app_name=MassTracker`, Native также передаёт User-Agent. Сервисы не оплачиваются и авторизация не требуется.

Сначала используются встроенные, свои и уже кешированные продукты. Принятые ответы сохраняются в локальную базу. Признаки объёма распознаются и в русском формате «250 мл» / «1 л». Отсутствующие/отрицательные/нечисловые данные не заменяются нулями; число пропущенных результатов объясняется. OFF может обозначать данные на 100 мл суффиксом `_100g`: продукты с признаками объёмной основы/жидких категорий пропускаются без выдуманной плотности. Для такого продукта можно создать запись по этикетке с данными на 100 г. См. [схему OFF](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product_nutrition/). Изображения допустимого HTTPS-хоста показываются при наличии, скрываются при ошибке; их офлайн-доступность не обязательна.

Камера поддерживает EAN-13, EAN-8, UPC-A и UPC-E. UPC-A и EAN-13 с ведущим нулём сопоставляются одному локальному продукту, в том числе офлайн. Native использует expo-camera, Web — ZXing из локального bundle; BarcodeDetector не требуется. Камера открывается явно, чтение блокируется после первого результата, поток освобождается при закрытии, уходе на другую вкладку и скрытии. Проверен сценарий позднего разрешения после закрытия/скрытия. Ручной ввод доступен при отказе/отсутствии камеры/сети; неизвестный продукт открывает создание с заполненным кодом.

## Хранение

Аддитивная миграция **3** SQLite/IndexedDB добавляет `food_diary_schema=1` в прежний `app_settings`. `food_diary_state` — JSON версии 1 с продуктами, записями, избранным и недавними. Встроенная база в bundle, повторного посева нет. Новая система хранения не вводилась.

Каждая запись содержит независимый снимок FoodProduct и пищевой ценности, количество, единицу, массу, локальную дату `YYYY-MM-DD`, MealType, ID и время создания. Правка/удаление исходного продукта не изменяет историю. Копирование создаёт новые ID. Суммы вычисляются из снимков выбранной даты без преобразования даты через UTC. Профиль, черновик, цели, тема и прежние данные остаются на месте.

Чтение/проверка и изменение документа защищены атомарным `SettingsStorage.apply(..., expected)` и прежней очередью commit PWA. Конкурентная транзакция отклоняется, UI предлагает перезагрузку дневника. Невалидный/неподдерживаемый JSON остаётся нетронутым. Подтверждение сохранения означает завершённую транзакцию. [Подробности](DATABASE.md).

## Ограничения и оставшаяся приёмка

Физический iPhone, системная клавиатура, реальное распознавание камеры, установленная PWA и Expo Go в этой сессии не проверялись. WebKit на Windows эмулирует браузер, а не аппаратную среду iPhone. Поэтому статус этапа не COMPLETED.

Safari/ОС могут очистить данные сайта, приватный режим/квота ограничивают IndexedDB. Автономность требует первой загрузки/подготовки кеша. Камера требует разрешения и HTTPS, ручной ввод работает без камеры. OFF требует сети, его полнота и доступность не гарантированы; изображения не обязательны для офлайн. Для неоднозначных жидкостей OFF не выводится фиктивная плотность. Резервное копирование и финальная публикация остаются этапом 15.

Открытые пункты: ручная приёмка физического iPhone, установленной PWA и Expo Go. Точные результаты автоматических проверок фиксируются выше. Для больших многолетних историй JSON читается целиком; оптимизация и отдельные индексы могут понадобиться позднее.
