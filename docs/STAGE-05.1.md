# Этап 05.1 — Справочник рецептов и умный поиск

## Требования к наполнению справочника

- Встроенный каталог должен содержать не менее **3 000 уникальных рецептов**, а общая база продуктов и ингредиентов — не менее **2 000 позиций**. Архитектура каталога должна поддерживать расширение до **50 000 рецептов**.
- Массовый импорт должен принимать JSON, CSV и совместимые открытые наборы данных. В каталог допускаются только данные из источников с лицензией, разрешающей их использование и распространение в приложении. Для каждого набора нужно фиксировать источник, версию, лицензию и требуемую атрибуцию.
- При импорте нужно нормализовать названия, единицы измерения и ингредиенты, автоматически проверять обязательные поля и корректность значений и удалять дубликаты внутри набора и относительно существующего каталога. Повторный импорт того же набора не должен увеличивать число записей.
- Для импортированных рецептов нужна русская локализация названий, ингредиентов и шагов приготовления. Каталог должен включать казахскую, узбекскую, русскую, итальянскую, азиатскую, американскую, грузинскую и турецкую кухни.
- КБЖУ нужно рассчитывать по количеству ингредиентов и достоверным данным об их пищевой ценности. Неполные или неподтверждённые данные следует отмечать при проверке качества. Фиктивные рецепты и случайные показатели пищевой ценности запрещены.
- Поиск по всему каталогу должен использовать индексы и работать офлайн. Весь текстовый каталог должен быть доступен без сети. Списки должны использовать виртуализацию, а изображения — загружаться лениво по мере просмотра. Первый запуск не должен загружать тысячи полноразмерных фотографий.
- Если подходящих источников недостаточно для достижения целевых объёмов, нужно реализовать механизм импорта и указать фактическое число проверенных уникальных рецептов и позиций продуктов и ингредиентов после проверки качества и удаления дубликатов.

## Текущее состояние справочника

Откройте «Питание → Рецепты». Разделы «Все рецепты», «Мои рецепты» и «Избранное» доступны в прежней вкладке. «Выбрать рецепт» в дневнике открывает тот же каталог. После расширения в комплекте **177 рецептов и 2 000 продуктов**. Импорт добавил 27 рецептов к 150 исходным и 1 552 продукта к 448 исходным. Ингредиенты содержат массы съедобной части, а рецепты — порции, подготовку, приготовление, сложность и пошаговые инструкции.

## Массовый импорт

Из корня репозитория запустите `python scripts/import-catalog.py <путь-к-кешу>`. Скрипт загружает исходные JSON и ZIP с CSV, проверяет SHA-256, формирует два TypeScript-модуля и записывает `rejected.json` в каталог кеша. Повторный запуск с теми же входами даёт те же файлы. Идентификаторы основаны на `fdc_id` и исходном `slug`. Таблица `scripts/catalog-ingredient-map.tsv` связывает ID и точное исходное название ингредиента с конкретной записью USDA и её справочными мерами. Русский текст рецептов взят из двуязычного источника. У части самостоятельных позиций USDA названия остались английскими.

Из 501 рецепта UniTools принято 27. Из 474 отклонённых у 455 первой причиной стало отсутствие проверенного соответствия ингредиента, у 13 отсутствовал поддерживаемый пересчёт меры или конкретная справочная масса, у 3 — количество, у 2 расчёт калорий существенно разошёлся с контрольным значением источника, у 1 совпало название. Граммы и килограммы нормализуются напрямую. Штуки и ложки пересчитываются по данным конкретного продукта, а для миллилитров нужна справочная масса указанной меры объёма. Соль и перец по вкусу указываются отдельно от расчёта КБЖУ. Для импортированных блюд источник не даёт выход готового блюда, поэтому доступны итоговые КБЖУ и КБЖУ на порцию. КБЖУ на 100 г доступны после ввода фактического выхода в своей копии.

Список показывает по 16 карточек на странице. Поисковый индекс сопоставляет слова с рецептами и сохраняет прежние правила ранжирования и фильтрации. Данные поставляются вместе с приложением и используют локальные иллюстрации. Импорт покрыл 25 кухонь. Объём 3 000 блюд и весь требуемый набор кухонь ещё не достигнуты. Индекс сейчас строится в памяти из рецептов, поэтому для объёма 50 000 потребуется хранение индекса на диске и загрузка записей по частям, с измерениями на физическом iPhone.

## Поиск и работа с рецептами

Поиск учитывает названия, состав, категории и теги. Запросы нормализуются по регистру, пробелам и е/ё. Словарь синонимов и одна опечатка в достаточно длинном слове помогают найти рецепт, а все значимые слова запроса должны получить совпадение. Клавиша поиска и открытие найденного блюда сохраняют до восьми запросов. Готовые подсказки доступны при пустой истории. Восемь подборок, комбинируемые фильтры, индивидуальный сброс меток, и сортировки доступны офлайн.

В режиме «Что приготовить из того, что есть» выберите продукты. Вода, соль и чёрный перец исключаются из расчёта при включённой настройке. Сопоставление учитывает стабильные ID продуктов, включая их состояние, поэтому сухой рис и варёный рис различаются. Результаты группируются по числу недостающих продуктов. Процент показывает наличие ингредиентов, без учёта запасов по массе. Исключение ингредиента действует по выбранному продукту, поэтому перед приготовлением при аллергии следует сверить состав и маркировку.

Подборки по дневным целям используют записи за выбранную дату. «Подходит под оставшиеся калории» проверяет одну порцию против остатка калорий. «Поможет добрать белок» проверяет ту же границу калорий и требует как минимум 20 г белка либо весь остаток, если он меньше. Быстрый завтрак занимает до 20 минут. Высококалорийный перекус начинается с 350 ккал на порцию. Подборка для набора массы использует теги рецептов.

Готовый рецепт можно добавить в избранное, масштабировать для приготовления, отметить ингредиенты и шаги, скопировать для редактирования либо записать как одну позицию питания. Отметки приготовления живут, пока открыта карточка. Снимок КБЖУ сохраняется вместе с порцией, выбранной датой и приёмом. «Сегодня» и цели читают тот же дневник.

## Диагностика Open Food Facts

Проверка с origin действующей PWA в Chromium и WebKit получила ответы `200` для известного штрихкода и `404` для отсутствующего продукта, оба с CORS. Ранее HTTP 404 мог отображаться как временная недоступность. Текстовый поиск дал `200` в Chromium и `TypeError` в WebKit. Прямой запрос зафиксировал также `503` без `Access-Control-Allow-Origin`. Браузер в таком случае скрывает HTTP-статус, поэтому сообщение описывает сбой соединения или недоступный ответ. Для исходного случая на iPhone точная причина неизвестна.

Клиент проверяет контрольную цифру штрихкода и различает отсутствие продукта, неполную карточку, неверный запрос, запрет, лимит, сетевой сбой, таймаут и ответ сервиса с ошибкой. Текстовый поиск запускается явно с локальным ограничением частоты. Альтернативный Search-a-licious в исследованных ответах не возвращал КБЖУ. Поиск по штрихкоду и существующий текстовый API вызываются напрямую. [Документация Open Food Facts](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/) · [Трекер CORS](https://github.com/openfoodfacts/openfoodfacts-server/issues/13475).

## Запуск и проверка PWA

```powershell
npm.cmd ci
npm.cmd run build:web
npm.cmd run verify:web
npm.cmd run serve:web
```

На компьютере откройте `http://127.0.0.1:4174`. Завершите анкету, дождитесь в профиле статуса «Доступно без интернета», затем отключите сеть и перезапустите приложение. Откройте «Питание → Рецепты», найдите «Банан молоко овсянка», совместите фильтры, отметьте ингредиент в режиме продуктов дома, добавьте блюдо в избранное и одну порцию в дневник. После повторного перезапуска проверьте избранное и запись на «Сегодня». Для проверок в Safari и установленной PWA используйте HTTPS-адрес разрешённой сборки и [инструкцию для iPhone](PWA.md#проверка-на-iphone). Для Expo Go на устройстве в той же сети используйте `npm.cmd run start -- --lan`.
