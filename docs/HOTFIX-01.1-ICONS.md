# HOTFIX 01.1 — PWA Icons Rendering

Дата проверки: 26 ноября 2026 года. Исправление ограничено этапом 01.1. Этап 02 не начат; публикация и git push не выполнялись.

## Причина

Исходный общий компонент `Icon` использовал `expo-symbols`: SF Symbols на iOS, локальный шрифт Material Symbols на вебе. Поэтому исчезновение шрифта одновременно затрагивало вкладки, профиль, стрелки, карточки и кнопки. Веб-реализация библиотеки асинхронно загружает шрифт; ошибка загрузки скрывается внутри библиотеки, а для символов используются private-use glyphs, которые не заменяются системным шрифтом.

На [опубликованном приложении](https://fitapp-epj.pages.dev/profile) проблема воспроизведена в Playwright WebKit. Запрос:

```text
/assets/node_modules/@expo-google-fonts/material-symbols/400Regular/MaterialSymbols_400Regular.e45456f641d122dacce5d620f0f8be96.ttf
```

возвращал `200`, `Content-Type: text/html; charset=utf-8` и 1397 байт HTML вместо TTF. В `document.fonts` статус `MaterialSymbols_400Regular` был `error`. В чистом браузерном контексте Cache Storage оставался пустым, сообщение «Доступно без интернета» не появлялось.

Файл присутствовал в локальном Expo-экспорте: 975812 байт, HTTP 200, `font/ttf`. Он также был указан в precache. Ошибка возникает на публикации: Cloudflare Pages исключает каталоги `node_modules`, включая вложенные в `assets`. Отсутствующий файл подменяется HTML через SPA fallback. [Официальное описание исключений Pages](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/#ignoring-assets) · [Исходная проблема Expo assets в workers-sdk](https://github.com/cloudflare/workers-sdk/issues/3615).

Service Worker проверяет SHA-256 каждого ресурса. HTML вместо TTF не проходит проверку, поэтому установка новой версии завершается неудачей и её незавершённый кеш удаляется. Путь содержит также ресурсы Expo Router: одной замены шрифтовых иконок было бы недостаточно для надёжного offline precache после публикации.

## Исправление

- Создан `AppIcon` с типом `AppIconName` и фиксированным набором из 32 Lucide SVG-иконок. Он использует `react-native-svg` на обеих платформах и не загружает шрифт, внешние SVG-файлы или CDN-ресурсы.
- Все вызовы старого компонента и типы SF Symbols заменены во всём приложении. Вкладки используют `House`, `Utensils`, `Dumbbell`, `ChartNoAxesCombined`, `UserRound`.
- Сохранены размеры 12–28 pt, отступы, исходные цветовые токены, фон активной вкладки и структура экранов. Иконки имеют единый контур и остаются декоративными для accessibility; подписи действий сохранены у кнопок и вкладок.
- Установлен `lucide-react-native` 1.80.0. Существующий `react-native-svg` 15.16.0 проверен через Expo install для SDK 58. Он включён в Expo Go; Lucide не добавляет нативных модулей. Удалены прямая зависимость `expo-symbols` и транзитивный Material Symbols. `expo-font` оставлен для совместимости остального Expo-стека.
- Используются публичные импорты `lucide-react-native/icons/...`, чтобы Metro включал только нужные иконки. В тестах подключается реальная CommonJS-сборка этих же иконок: Jest не исполняет выбранный React Native условием `.mjs` entry без дополнительной ESM-настройки. Иконки не замоканы.
- Добавлен Metro asset plugin: только в production-экспорте пути `/node_modules/` преобразуются в `/vendor/` до генерации JS, выходных файлов и их хешей. Это сохраняет согласованность ссылок и precache, не меняя нативные и dev-пути. Команда экспорта остаётся прежней.

Совместимость `react-native-svg` 15.16.0 с SDK 58 и Expo Go указана в [документации Expo](https://docs.expo.dev/versions/v58.0.0/sdk/svg/).

## Service Worker и данные

Существующий механизм автоматически вычисляет версию по содержимому сборки, включая JS и список ресурсов с контрольными суммами. Поэтому ручной счётчик версии не добавлялся. Проверенная смена кеша:

```text
masstracker-app-b68e3dd64eea9a997989
→ masstracker-app-0f3bcd03874a431ec653
```

Новая версия кеширует 35 URL, включая оболочку и 18 файлов `/assets/vendor/`. В precache нет путей `/node_modules/` и шрифтовых файлов. SVG находятся в кешируемом JS. Старый кеш удаляется существующей логикой после активации новой версии.

Обновление по кнопке «Обновить» проверено в Edge и WebKit на одном origin со старой кешированной сборкой: версия IndexedDB осталась 1, значение `theme_mode=dark` и отдельная контрольная запись сохранились. Код базы, миграций и обновления пользовательских данных не менялся. Очищать данные сайта для обновления не требуется.

Пройдено: production-экспорт в `dist`, включая `sw.js`. Отдельный файл Material Symbols отсутствует; ресурсы зависимостей экспортируются в `assets/vendor/`. Их URL, контрольные суммы и доступность проверены установкой SW и offline-запуском.

В PowerShell использовались `npm.cmd` и `npx.cmd`, поскольку политика выполнения блокирует `.ps1` launchers. Это те же команды npm/Expo. При экспорте Node выводил предупреждение о совместно заданных `NO_COLOR` и `FORCE_COLOR`; сборка завершилась с кодом 0.

## Expo Go и ограничения

Дополнительно выполнен `npx expo export --platform ios --output-dir .expo/icon-hotfix/ios`: сформирован Hermes bundle. Первая попытка внутри Windows-песочницы завершилась ошибкой записи Hermes во временный каталог; повтор вне песочницы прошёл. Версии SDK и нативных зависимостей не менялись.

Физический iPhone недоступен. Playwright WebKit на Windows и эмуляция standalone не заменяют Safari на iPhone, реальную установленную PWA и Expo Go. После согласованной публикации остаётся ручная приёмка на устройстве: обе темы, все вкладки и стрелки, запуск с экрана «Домой» в авиарежиме и обновление с сохранением данных. На production-домен исправление пока не опубликовано.
