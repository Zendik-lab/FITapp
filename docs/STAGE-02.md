# Этап 02 — анкетирование и персональные цели

26.11.2026. Код реализован в существующем MassTracker. Этап остаётся `IN_PROGRESS` до ручной приёмки на физическом iPhone. Этап 03 не начат, публикация и git push не выполнялись.

## Что реализовано

Восемь шагов: приветствие, личные сведения и параметры тела, выбор цели, целевой вес и темп, активность, тренировки, необязательные пищевые сведения, редактируемая сводка. Возраст считается по дате рождения. Поддерживаются набор, снижение и поддержание веса, пять уровней активности, отсутствие тренировок, тип и опыт тренировок. Пищевые сведения включают режим, приёмы пищи, исключённые продукты, аллергии и ограничения.

Новый пользователь видит анкету до вкладок. Черновик и индекс шага сохраняются после каждого изменения через общий локальный API. После перезапуска открывается последний подтверждённый шаг. Ошибка записи сохраняет введённые значения на экране и позволяет повторить операцию. Завершение записывает профиль и признак завершения атомарно, после чего открывается «Сегодня» даже при входе по прямому URL другой вкладки. Завершивший анкету пользователь сразу получает прежние пять вкладок.

В профиле отдельно редактируются личные данные, параметры тела, цель, активность, тренировки и пищевые предпочтения. Сохранение подтверждается после commit. Выход из изменённого раздела требует подтверждения. Повторное анкетирование также требует подтверждения, подставляет текущий профиль и сохраняет остальные данные и настройки. Тема и установка PWA остаются в настройках приложения.

«Сегодня» показывает сохранённые имя, текущий и целевой вес, цель и разницу. Калории и БЖУ показывают отсутствие расчётов. Остальные демонстрации предыдущих этапов сохранены. Название продукта MassTracker, темы, системная типографика, SVG-иконки и навигация сохранены.

## Хранение и правила

`ProfileDraft` хранит строки, включая незаконченные числа. `UserProfile` объединяет `personal`, `body`, `goals`, `activity`, `training`, `nutrition`; числовые значения нормализуются при подтверждении. `UserState.onboarding` содержит `completed`, `step` (0–7), `draft`. Возраст вычисляется, а не хранится.

Аддитивная миграция 2 добавляет `user_state_schema=1` в существующий `app_settings`. Ключ `user_state` содержит версионированный JSON; профиль и состояние анкеты обновляются одной транзакционной записью. В браузере используется IndexedDB, в Expo Go — существующий слой SQLite с параметризованным UPSERT. Backend и регистрация не нужны. [Полная схема](DATABASE.md#версия-2--профиль-и-анкетирование).

Общая очередь `settings-writes.ts` регистрирует принятые записи сразу. Обновление PWA ожидает всю очередь; ошибка записи отменяет обновление. Кнопка обновления блокируется для несохранённой формы. Повреждённый или неизвестный формат профиля вызывает ошибку без очистки хранилища.

- Имя: 1–80 символов после trim. Дата: существующая ДД.ММ.ГГГГ, не позже сегодня, возраст до 120 лет; високосные дни проверяются.
- Рост: 80–250 см; текущий и целевой вес: 20–400 кг. Принимается десятичная запятая. Пустые числа, NaN, Infinity, единицы в поле и экспоненциальная запись отклоняются.
- Целевой вес должен соответствовать направлению цели. При поддержании он равен текущему и обновляется вместе с ним.
- Рекомендованный начальный ориентир: 0,25 кг/неделю; пользовательский: 0,05–2. При поддержании — 0. Дата результата не рассчитывается и не обещается.
- Тренировок: целое число 0–14; при 0 тип и опыт необязательны. Приёмов пищи: 1–10 или пусто. Пищевые текстовые поля ограничены 1000 символами.
- При темпе выше 1% текущего веса в неделю, возрасте младше 20 лет и необычном целевом весе относительно роста показывается предложение обсудить цель со специалистом. Это предупреждение, не диагноз и не автоматический запрет.

Ориентиры ИМТ для взрослых ниже 18,5 и от 30 основаны на [CDC](https://www.cdc.gov/bmi/adult-calculator/bmi-categories.html); они не учитывают состав тела. [NHS описывает постепенный набор веса](https://www.nhs.uk/live-well/healthy-weight/managing-your-weight/healthy-ways-to-gain-weight/). Конкретные 0,25 кг/неделю — начальная настройка продукта, а не персональная медицинская рекомендация. Калькуляторы калорий и БЖУ не реализованы.

```powershell

```

Production PWA локально:

```powershell

```

Откройте `http://127.0.0.1:4174`. Для установленной PWA на iPhone нужен HTTPS origin. Публикация этой версии требует отдельного разрешения. Данные разных origin и Expo Go не переносятся автоматически.

Expo Go:

```powershell
Set-Location -LiteralPath 'D:\FitApp'
npx.cmd expo login
npm.cmd run start -- --lan
```

Установите Expo Go с поддержкой используемого SDK 58, войдите в ту же Expo-учётную запись, подключите iPhone и компьютер к одной Wi-Fi сети. Отсканируйте QR-код Камерой. При проблемах LAN остановите Metro и используйте `npm.cmd run start -- --tunnel`. Не очищайте данные существующей PWA ради теста: в профиле есть подтверждённое повторное анкетирование.

## Ручная приёмка на iPhone

1. В Expo Go открыть проект. На чистом хранилище проверить приветствие, отсутствие вкладок до завершения, восемь шагов, прогресс и кнопки назад.
2. Ввести личные сведения. Проверить возраст, ошибку для 31.02 и будущей даты, пустые поля, запятую в весе, клавиатуру, прокрутку и доступность нижних кнопок.
3. В середине анкеты дождаться «Ответы сохранены на устройстве», полностью закрыть Expo Go и открыть проект вновь. Проверить шаг и значения.
4. Проверить три цели, соответствие целевого веса цели, рекомендованный / свой темп и предупреждения. Обещания даты результата быть не должно.
5. Выбрать 0 тренировок, затем несколько с типом и уровнем. Пропустить пищевые сведения. Проверить сводку, возврат к разделам и создание профиля.
6. Проверить переход на «Сегодня», имя, вес, цель, разницу и отсутствие расчётов калорий / БЖУ. Перезапустить: анкета больше не открывается.
7. Изменить каждый раздел профиля, сохранить и открыть заново. Проверить отмену правок, темы и изменение текущего веса при поддержании.
8. Повторное анкетирование сначала отменить, затем подтвердить. Проверить заполненные ответы, сохранение темы и прочих данных. Закончить повторную анкету.
9. После разрешённой публикации повторить сценарии в Safari и установленной PWA. Дождаться офлайн-готовности, включить авиарежим, полностью закрыть и открыть приложение. Проверить профиль, Safe Area, клавиатуру, VoiceOver, темы и отсутствие горизонтального скролла.

## Известные ограничения

- Физический iPhone, Safari standalone и Expo Go вручную не проверялись; автоматизированный WebKit не заменяет приёмку.
- Редактор раздела сохраняется по кнопке: неотправленные правки не восстанавливаются после принудительного закрытия процесса. Анкета восстанавливает уже подтверждённые хранилищем записи. При полном отказе хранилища нельзя обещать сохранение.
- Safari может очистить данные origin. Резервное копирование относится к этапу 15.
- Дата рождения вводится текстом; режим питания — свободный текст. Изменения нескольких одновременно открытых окон не объединяются: используйте одно окно для редактирования.
- Планирование еды, расчёты, дневники, Health, уведомления, облако и прочие будущие функции не добавлялись. Публикация не проводилась.
